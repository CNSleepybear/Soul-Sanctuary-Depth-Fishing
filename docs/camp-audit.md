### 节奏分析

**核心问题：精华（Essence）是全局瓶颈。** 金币获取速度约为精华的 3 倍（280g vs 12e = 23:1），但大多数升级的金币:精华比在 15:1 到 20:1 之间。这意味着：

1. **前 6 个 run（新手期）**：charm_rerolls 和 bait_pouch 的低级升级很快完成，玩家有成就感
2. **7-15 个 run（瓶颈期）**：所有升级线同时进入 Lv2-Lv3 区间，精华需求暴增。玩家每次回营地看到 4 条升级线都"差一点精华"，但金币已经够。**这是最容易流失的阶段。**
3. **16+ 个 run（后期）**：relic_slots Lv3 的 120 essence 成为终极墙。按每 run 约 12 essence 计算，需要 **连续 10 个 run 不花任何精华** 才能完成。如果玩家中间买了其他东西，可能需要 15+ runs。

**量化结论**：从新手到满级，全升级线完成需要约 **45-55 个 run**（每次 run 约 10-15 分钟），即 8-14 小时游戏时间。但瓶颈期（7-15 run）的感受远差于前期，因为升级速度从"每次回营地都能买"骤降到"攒 3-4 个 run 才能买一次"。

- **状态**: ⚠️ 有风险
- **当前实现**: [`CampManager.ts:18-69`](src/renderer/roguelike/CampManager.ts:18) — 5条升级线，costScale 从 1.4 到 2.0 不等。精华通过 [`GameStateManager.addEssence`](src/renderer/core/GameStateManager.ts:172) 累积，来源仅有 run 奖励（`fishCaught × 1.5`）和 daily quest 奖励。
- **玩家感受**: "前3趟run我每趟都能升级，感觉很爽。但从第4趟开始，我看着1200金币但只有28精华，什么也买不了。连续3趟run都这样——我开始觉得是不是自己运气不好。"
- **优化建议**:
  1. 在 [`CampManager.ts`](src/renderer/roguelike/CampManager.ts) 中为前 3 个 run 增加"新手加速"：第一次购买任意升级享受 50% 精华折扣（通过 `GameStateManager` 检查 `totalRunCount < 3` 时调用 `purchaseDiscounted`）
  2. 在 Camp 面板每个升级行旁增加进度条：`当前精华 / 所需精华`（如 `28/32 ✨ ████████░░ 87%`），让玩家看到"还差一点"而非"差很多"
  3. 为瓶颈期（run 5-10）增加临时精华来源：在 result panel 增加"精华奖励任务"（如"连续3次perfect catch = +5 essence"）
- **预期效果**: 瓶颈期流失率降低 30-40%。玩家从"看不到希望"变为"知道还差2个run"。

## 7.2 涌现性 — 升级路径是否只有一种最优解？

### 当前路径分析

5 条升级线的顺序没有硬性约束——玩家可以自由选择。但经济系统创造了**隐性最优路径**：

1. **强制第一步：relic_slots Lv1** — 新玩家初始拥有 `relic_compass`（[`GameStateManager.ts:78`](src/renderer/core/GameStateManager.ts:78)），但 `DEFAULT_RELIC_SLOTS = 0`。玩家能看到 relic 图标但灰色不可用。这是游戏设计中著名的"可见但不可用的奖励"模式——它创造了一种不舒服的拥有感。玩家被迫在 2-3 个 run 内优先攒 500g + 30e。

2. **最优第二步：charm_rerolls Lv1** — 只需 150g + 8e（1 run），但能多一次重骰机会，直接提升 charm 质量。

3. **最优第三步：charm_slots Lv1** — 200g + 10e，第四个 charm 槽位大幅提升 synergy 发现概率。

4. **第四步以后**：随意。但 bait_pouch 对实际 fishing 影响最小（bait 系统尚未完善），而 line_durability 是纯防御性升级——玩家天然倾向于先买"进攻"后买"防御"。

**实际路径 = relic_slots Lv1 → charm_rerolls Lv1 → charm_slots Lv1 → ... → line_durability（最后）**

这意味着 5 条线实际上只有 1 条路径：所有玩家以几乎相同的顺序升级。

- **状态**: ❌ 缺失
- **当前实现**: 升级线完全独立，无前置条件，无互斥选择，无分支。在 [`CampManager.ts:18-69`](src/renderer/roguelike/CampManager.ts:18) 中每条线的 `apply` 函数只修改 meta 的单一字段。在 [`RunUI camp panel:190-210`](src/renderer/roguelike/RunUI.ts:190) 中升级行按固定顺序渲染，无优先级提示。
- **玩家感受**: "每次回营地我感觉就是在做同一件事——看哪个我能买得起，点一下。没有'我是走charm流还是走relic流'的选择感。所有升级都是'更好'，没有'不同'。"
- **优化建议**:
  1. **引入"专精选择"**：在 CampManager 中增加一个 `specialization` 字段。当玩家累计购买了 3 个非 relic_slots 升级后，解锁选择："Charm Master"（charm slots+1，但 line durability-20%）或 "Line Master"（line durability+50%，但 charm slots-1）。此选择永久绑定，不可更改。
  2. **升级互斥**：将 bait_pouch 和 line_durability 的 Lv3-Lv5 设为互斥——升满一条线的 Lv5 将锁定另一条线的 Lv4+。迫使玩家在"更多bait = 更多稀有鱼"和"更强线 = 更安全"之间做出有意义的选择。
  3. **Relic 驱动路径**：不同 relic 应该影响升级策略。例如拥有 "Dragon Gut Line" 的玩家可能不需要 line_durability 升级；拥有 "Echo Stone" 的玩家可能更需要 charm_slots。在 relic 描述中加入暗示（"此 relic 与 line durability 升级有协同效应"）。
- **预期效果**: 从"一条路走到黑"变成至少 3 条有意义的 build 路径（Charm 流 / Line 流 / Relic 流）。重玩价值显著提升。

## 8.2 低谷缓冲 — 失败后回营地的情感体验

### 断线后的玩家旅程

场景模拟：玩家第 5 个 run，选择了 3 个 charms，在钓到 2 条 common 鱼后，咬到一条 rare 鱼，在 reeling 时张力冲顶断线。run 以 2 条鱼结束。

**Step 1：结果面板**（[`RunUI._showResultPanel`](src/renderer/roguelike/RunUI.ts:457)）
```
🧲🧘🍀          ← 这趟run的3个charms（现在没用了）
🐟 2 · ⭐0      ← 只钓了2条，0个perfect
💰 +32 · ✨ +3  ← 微薄收益
[Back to Camp]  [Fish Again]
```

**Step 2：营地面板**（[`RunUI.showCampPanel`](src/renderer/roguelike/RunUI.ts:157)）
- 顶栏显示：💰532 ✨23
- 地点选择器：12个地点，只有 Japan 解锁
- 升级列表：每行显示高昂价格（"Charm Slots Lv1: 200G 10✨"——买不起）
- Relics：compass 灰色（0 relic slots，无法装备）
- 成就：大部分 🔒
- 底部："Start Expedition" 绿色按钮

### 情感曲线分析

| 时刻 | 玩家情绪 | 设计问题 |
|------|----------|----------|
| 断线瞬间 | 😤 挫败 | 红色弹窗 + 鱼跑了 |
| 结果面板 | 😐 平淡 | 没有安慰，只有冷数字 |
| 回营地 | 😞 失望 | 所有升级都买不起，relic 用不了 |
| 看升级 | 😣 焦虑 | "我还需要攒很久" |
| 点 Start | 💪 再试 | 唯一正向出口 |

关键问题是 **Step 2→3 之间的落差**：玩家从"我钓到了鱼"短暂正面 → 看到升级列表发现"什么都买不起"→ 迅速掉入负面。

- **状态**: ⚠️ 有风险
- **当前实现**: 
  - 结果面板标题固定为 "Run Complete"，无论实际收益多少（[`RunUI.ts:467`](src/renderer/roguelike/RunUI.ts:467)）
  - 无"距下一升级还有多远"指示器
  - 无失败专属安慰内容
  - 无"你这次获得了新的 fishpedia 记录"提示（即使 2 条鱼也是新记录）
- **玩家感受**: "断线后回到营地，看到那些我买不起的升级，感觉自己在原地踏步。如果我能看到'再钓2趟就能买 charm slots'，我可能不会关掉窗口。但现在我只看到昂贵的数字。"
- **优化建议**:
  1. **结果面板情绪分级**：根据 run 收益动态改变标题和色彩。
     - 收益 ≥150g："🎉 Expedition Success!" (金色)
     - 收益 50-149g："📋 Expedition Complete" (白色)
     - 收益 <50g 或 run 以断线结束："🕯️ A Short Trip" (暖灰，暗示"旅途虽短，仍在路上")
  2. **营地面板"最近进度"区域**：在 upgrades 上方增加一个紧凑的进度条，显示玩家当前最接近能购买的升级。例如：
     ```
     🎯 Next: Charm Slots Lv1 — 💰200/200 ✅ ✨10/28 ████░░░░ 36%
     Estimated: ~2 more runs
     ```
     实现位置：在 [`RunUI.showCampPanel`](src/renderer/roguelike/RunUI.ts:157) 的 gold/essence 显示行之后、upgrades 之前。
  3. **失败后的正向锚点**：在 result panel 的 "Fish Again" 按钮旁增加小字提示——从 fishpedia 中提取一条只有本 run 才可能触发的正面信息："📖 You discovered: Sakura Koi! (new record: 17.8cm)"（如果 run 中有新记录）；"📊 Total catches: 47 — 3 away from achievement!"（如果接近成就）。
- **预期效果**: 失败后的"直接退出"率降低 50% 以上。玩家从"看不到进展"变为"看到了一个明确的下一个里程碑"。
